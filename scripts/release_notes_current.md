## 0.1.0-dev.32

- Fix macOS AWS Chime `WKWebView` video frame pumping: compute `frameSignature` from `presentedFrames` and `mediaTime` in `aws_desktop_runtime.js` (so WebKit `MediaStream` frames with `mediaTime === 0` are not dropped after the first frame), mute and call `play()` on Chime `<video>` tiles and replay remote `<audio>` on `loadedmetadata` / `chooseAudioOutput` in `chime-session.js`, place the bridge `WKWebView` inside visible view bounds with hit-testing disabled (`PassiveBridgeWebView`), and emit `videoTileSizeChanged` when track dimensions update.
- Preserve full uncropped video framing by default (Scheme A: `BoxFit.contain`) across `RealtimeLiveVideoStage`, `RealtimeSelfView`, `RealtimeMeetingStage`, and `RealtimeVideoGrid`, while letting users switch between full video (`BoxFit.contain`) and fill screen (`BoxFit.cover`) in both `RealtimeMeetingPage` and `RealtimeLivePage` (keeping screen shares and whiteboards at `BoxFit.contain`).
- Forward `videoTileSizeChanged` dimensions into `ChimeMeetingSession` snapshots and add native `fit` (`contain` / `cover`) support across `ChimeTrackRenderer` (iOS, Android, macOS, Windows), `TrtcTrackRenderer` (`setLocalFillMode` / `setRemoteFillMode`), `IvsTrackRenderer` (iOS, Windows), and `ProviderWebTrackRenderer` (Web `objectFit`).
- Verification status: JS bridge tests (`43/43`), AWS desktop runtime tests (`10/10`), touched package `flutter analyze` and `flutter test`, `check_sdk_architecture.py`, `check_sdk_quality.py`, and macOS 2-peer Chime remote A/V frame check (`90` frames received in 6s) pass; multi-device iOS/Android physical verification of cross-orientation Chime framing remains pending user confirmation.
